# The Engineering Journey

Building UniHack was not a straight path. Implementing complex, autonomous AI agents locally using constrained models revealed significant engineering challenges, particularly around formatting, output constraints, and architecture.

This document tracks every major failure encountered and the engineering solutions we implemented. We do not hide our failures; they are the foundation of our robust architecture.

| Stage | Failure | Exact Symptom | Root Cause | Fix | Verification | Final State |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| Initial Setup | Ollama 404 | `Client error '404 Not Found' for: http://127.0.0.1:11434/api/chat` | The `engine_service.py` was hardcoded to route `freellmapi` and `xai` models but defaulted to Gemini for everything else, sending Gemini models to the Ollama endpoint. | Implemented deterministic routing to ensure the local Ollama provider receives the correct `qwen3.5` model name. | API calls successfully reached Ollama. | Fixed: Ollama handles LOCAL traffic. |
| Schema Design | Pydantic Mismatch | `TypeError: string indices must be integers` | A function expected `required_attributes` to be a string, but Pydantic was passing a dictionary. | Adjusted the Pydantic model and parsing logic to correctly handle the nested dictionary structure. | Unit tests passed. | Fixed: Schemas align. |
| AI Inference | Empty Qwen Response | `ValueError: No JSON object or array found` | The model response was entirely empty because it was overwhelmed by context or lacked explicit generation instructions. | Adjusted prompts to enforce strict output formats. | Model began returning text. | Fixed: Output generation stabilized. |
| AI Inference | 512-Token Truncation | `JSONDecodeError: Expecting ',' delimiter` | The default Ollama `num_predict` was truncating the model's output mid-JSON. | Increased `num_predict` to 1500. | Longer outputs succeeded. | Iteration 1 |
| AI Inference | 1500-Token Truncation | `ValueError: No JSON object or array found` | Qwen3.5 produces a massive "Thinking Process" before the JSON. 1500 tokens were not enough to finish the thought process, truncating the output before the JSON even started. | Removed `num_predict` caps entirely (`num_predict: -1`) to allow unlimited generation for deep reasoning. | Local inference took longer but completed fully. | Fixed: Truncation eliminated. |
| Prompt Engineering | Anti-think instruction failure | Model outputs `<thought>` blocks anyway. | Qwen3.5 is heavily instruction-tuned to reason before answering and frequently ignores negative constraints like "DO NOT think". | Stopped fighting the model. Allowed it to think, and built a robust JSON extractor to parse the output instead. | Logs show thoughts are generated but safely ignored. | Fixed: Model quirks absorbed. |
| JSON Parsing | Extra data | `JSONDecodeError: Extra data` | The AI output contained multiple JSON blocks or markdown text surrounding the JSON. | Replaced `json.loads` with a robust scanner using `json.JSONDecoder().raw_decode()`. | Extractor isolated JSON safely. | Iteration 1 |
| JSON Parsing | list/dict mismatch | `AttributeError: 'list' object has no attribute 'get'` | The prompt asked for multiple data structures (Identity and Actions). Qwen split them into two separate Markdown JSON blocks. The naive parser grabbed only the last block (the list) when a dict was expected. | Rewrote `_parse_json_response` to iteratively scan the *entire* text, extract *every* valid JSON object, and deep merge them into a single coherent dictionary. | DiscoveryAgent successfully parsed the product identity. | Fixed: Parser handles fragmented LLM output. |
| AI Routing | FreeLLMAPI 429 | `429 Too Many Requests` | The pipeline erroneously routed to the external proxy during a LOCAL run because the batch endpoint dropped the `ai_mode` flag. | Fixed the batch endpoint to properly propagate the `ai_mode` through the frontend and backend. | Local runs stay local. | Fixed: True LOCAL execution. |
| Execution | Final Schneider run | End-to-end pipeline succeeded. | All architectural boundary fixes were in place. | The application successfully completed a fresh-product run. | Verified via UI and database. | SUCCESS |

### Key Lesson Learned
**Do not fight the model.** Our biggest breakthroughs came when we stopped trying to force Qwen3.5 to output perfect, strict, thought-free JSON via prompt engineering, and instead allowed it to generate its natural verbose output, building robust deterministic systems in Python to extract and normalize the data downstream.
